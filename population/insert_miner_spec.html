The Insert-Miner

From “what is this product” to “what is legally true inside the box.”
Spec only — Chat → Agree → Cowork → Code. No build until you say go. · 2026-07-20

The package insert is not a page — it is a document with its own identity. In GS1 terms a document carries a GDTI (Global Document Type Identifier). The insert-miner extends docmine to mint a CANDIDATE GDTI for the insert, bind it to the product’s GTIN, segment the regulated sections that its labeling regime requires, and lift the safety content — adverse reactions, contraindications, allergens, interactions — into a first-class binding set the graph can query.

1 · What we are identifying

Two identities and one binding, all issued by one party.

ThingID typeURNStatus
The product (the box)GTIN / SGTINurn:epc:id:sgtin:…candidate leading-substring (prefix never derived)
The insert (the leaflet)GDTIurn:epc:id:gdti:CompanyPrefix.DocType.SerialCANDIDATE
IssuerPGLNurn:epc:id:pgln:…the party holding the prefix
PGLN (issuer)──issues──▶ GTIN (product)──has_regulated_document──▶ GDTI (insert)
Hard rule carried through. The insert is issued by the same registrant that holds the product’s company prefix. So the GDTI’s company prefix equals the GTIN’s company prefix — which we hold only as a candidate leading substring (variable-length, never derived). Therefore the whole GDTI — prefix, doc-type code, serial — is candidate until R4 ratification by the answerable party. Absence of a known serial is a CANDIDATE, never a fabricated one.

2 · The insert is not one format — it is a regime

“Less regulation” for supplements doesn’t mean a different tool. It means a smaller required-section set. The miner detects the labeling regime and applies the matching section grammar. Build the strict pharma case; relax down to supplements. Pharma is the hard case that generalizes.

RegimeBasisRequired sections (registrar-strict subset)
Rx Prescribing Information (PI)US PLR (21 CFR 201.56/57)Indications, Dosage & Admin, Dosage Forms/Strengths, Contraindications, Warnings & Precautions, Adverse Reactions, Drug Interactions, Use in Specific Populations, How Supplied/Storage
OTC Drug Facts21 CFR 201.66Active ingredient, Purpose, Uses, Warnings, Directions, Other information, Inactive ingredients
EU SmPCQRD template§4.1 Indications, §4.3 Contraindications, §4.5 Interactions, §4.8 Undesirable effects, §4.9 Overdose
Supplement FactsDSHEA / 21 CFR 101.36Serving size, Servings/container, Amount per serving + %DV, Other ingredients, “Contains:” allergen line, DSHEA disclaimer
This is the meta-configurator, not a fork. Each regime is a SHACL shape set over one “regulated-document” template. The insert-miner is our meta-configurator engine pointed at documents instead of protocols — same shape_* machinery that already made the mfg workcell and the afo-lab protocol CONFORM on one engine.

3 · The SAFETY binding set first-class

binding_sets.py already renders binding sets. We add one type: SAFETY — the highest-liability, highest-value binding, and the reason a ThingSite becomes legally load-bearing.

MemberExtracted asCandidate coding (never fabricated)
Adverse reactionsentity list per sectioncandidate → MedDRA (unmapped = candidate)
Contraindicationsentity listcandidate condition terms
Allergensthe “Contains:” statementcandidate → controlled allergen list (US big-9)
Interactionsedges to other substances/GTINscandidate substance identity
The interaction row is the payoff. A drug/supplement interaction is an edge between two identified things → once bound, the graph answers “what interacts with what” across products. That is a capability off the graph, not a document lookup — and it is exactly the semantic-restoration thesis applied to safety.

4 · Conformance — registrar stricter than the regulator

GenSpecs / FDA say what a label may contain. ThingDaddy says what is issuable. Four shapes on the regulated-document template:

ShapeConstraintViolation →
shape_regime_required_sectionsevery required section for the detected regime is presentINCOMPLETE (flagged, not issued)
shape_gdti_prefix_matches_gtinGDTI company prefix is consistent with the bound GTIN’s prefixREJECT (cross-registrant insert)
shape_safety_binding_presentan Rx product’s PI has a non-empty SAFETY setINCOMPLETE
shape_allergen_controlledallergen maps to the controlled vocabularyfree-text allergen stays CANDIDATE, not ratified

A PI missing Contraindications is incomplete, not a valid registry entry. Stricter than the standard, never looser.

5 · Inputs — and your rare asset

Three input adapters feed one miner, mirroring how roster_harvest and docmine already feed website_agent:

  • PDF — existing docmine extractor (PyMuPDF → pdfminer).
  • URL pointer — sanctioned fetch only; no bot-block engineering; map-to-nothing (hold the pointer, not the payload).
  • Image (OCR) — follow-on capability, needs an OCR dependency. This is where your corpus lands.
NutriFacts / PharmaFacts / SupplementFacts. Your teams photographed every GTIN-labeled product across Canada, Belgium, Switzerland, Mexico. That is a GTIN ↔ physical label ↔ insert ground-truth corpus almost no registrar can assemble. The photo does double duty: it feeds the miner and it verifies the extracted insert against the physical artifact — machine ground truth (WS4). The barcode, the label, and the leaflet in one frame is the binding evidence.

6 · Outputs — ingest-ready, no spreadsheet

Per insert, candidate records carrying status (candidate | ratified) and provenance (source, extractor version, timestamp):

gdti_candidate   { gdti_urn, doc_type?, regime, issuer_pgln?, bound_gtin, status:"candidate" }
section[]        { section_code, regime, heading_verbatim, text_pointer, fields{…} }
binding_set      { type:"SAFETY",
                   adverse_reactions[], contraindications[], allergens[],
                   interactions[ {subject_gtin, object_substance?, candidate:true} ] }
provenance       { source_url|photo_asset_id, extractor_ver, ts, sanctioned:true }

  • Extend docmine.py with an --insert mode + a shared section_grammar.py (regime detection + per-regime headers). Don’t fork the PDF extraction.
  • Reuse the meta-configurator engine for the four shapes — the regulated-document template is a new entry in TEMPLATES, not new engine code.

8 · IP to flag (standing task — route through counsel before reliance)

  • Prefix-inheritance constraint: a GDTI insert inherits the bound product’s company prefix as a candidate; cross-registrant inserts are rejected. (TD-M candidate.)
  • Safety binding as graph edges: interactions become substance↔substance edges enabling cross-product interaction queries. Sketch core claim.
  • Regime-detection → SHACL-shape selection for regulated documents (meta-configurator specialization).
  • Photographed-label as machine ground truth verifying an extracted insert against the physical artifact. Sketch core claim.

9 · Boundaries — what it will not do

  • Never fabricate a GDTI prefix, doc-type code, or MedDRA/allergen code — all candidate.
  • No medical advice, no interpretation of the insert — extract and bind structure only.
  • Simulated inserts stay sim-lane; never enter the registry as truth.
  • No engineering around bot-blocks — sanctioned fetch or provided assets only.
  • Copyright: hold pointers + structured fields, not full-text republication (map-to-nothing).
